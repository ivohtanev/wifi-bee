# Wi-Fi Bee

Терминална програма за запис и анализ на Wi-Fi кадри и офлайн речникова проверка на собствени WPA/WPA2-PSK записи. Менюто е на български. Използвай я за своя мрежа или с разрешение на нейния собственик.

Програмата управлява `dumpcap`, `tshark`, `hcxpcapngtool` и `hashcat`. Има пълен запис, запис с намален служебен шум, статистика на живо, анализ на серии, експорт за Hashcat, изтегляне на речници и възобновяване на задачи. Не изпраща deauthentication команди и не гарантира възстановяване на парола.

## Системни изисквания

Основната целева среда е **Linux със systemd**, Bash, Python 3 и UTF-8 терминал с curses. Препоръчителна отправна точка е Ubuntu 26.04 LTS. Windows и macOS не се поддържат директно: кодът използва Linux интерфейси, `iw`, Unix права и `systemd-inhibit`. Други Linux дистрибуции не са проверени.

За нова инсталация използвай Python 3.10 или по-нов със стандартните модули `curses` и `fcntl`; текущата проверена версия е 3.14.4. Python 3.10 е консервативна препоръка, а не измерен минимален праг. Основната конзола няма външни Python зависимости и не изисква `pip` или виртуална среда.

За радиозапис са необходими Wi-Fi адаптер и Linux драйвер с **monitor mode**, разрешен канал и `sudo` достъп. Само поддръжка на Wi-Fi/802.11ax не е достатъчна. За офлайн Hashcat проверка не е нужен Wi-Fi адаптер, но е нужен работещ CUDA/OpenCL backend. GNOME е необходим само за отделния `sleep-settings.py`.

| Компонент | Конфигурация и значение |

| Python | `/usr/bin/python3`: 3.14.4 |
| CPU | Intel Core i5-13420H, 12 логически процесора |

Това е отчет за разпознатата среда, не гаранция за всички канали, едновременно managed/monitor поведение или скорост на проверка. CUDA и OpenCL записите в `hashcat -I` могат да са два backend-а за една физическа карта.

Няма измерен минимален праг за RAM/CPU. Повече памет и бърз SSD помагат при големи записи. Осигури място за оригиналните PCAPNG, временни копия при анализ, TSV експорт и резултати. Анализът копира избраните файлове във временна папка; кеш експортът пази още едно копие на оригиналите. Провери свободното място и в `/tmp`, `/var/tmp` и папката на проекта.

Записът **няма автоматично изтриване на стари файлове или спиране при ниско свободно място**. Всеки файл се ротира при 50 000 KiB (около 48.83 MiB) или 2000 секунди, което настъпи първо. Общият размер на серията е неограничен.

## Пакети и защо са нужни

Следните команди са за Ubuntu. Основните пакети от таблицата вече бяха налични на проверената машина; инсталационните команди са за възпроизвеждане на средата.

| Пакет | За какво се използва | Необходимост |
| --- | --- | --- |
| `python3` | Изпълнява конзолата и помощните модули; curses е терминалният интерфейс | Задължителен |
| `bash` | Изпълнява `wifi-monitor.sh` | Подготовка на monitor интерфейса |
| `sudo` | Дава правата за интерфейса, записа и собствеността на файловете | Текущата конзола изисква root |

| `rfkill` | Проверява блокирано радио и премахва софтуерна Wi-Fi блокировка | Използва се от `wifi-monitor.sh` |
| `iproute2` | Предоставя `ip` за активиране на интерфейс и преглед на маршрута | Използва се от `wifi-monitor.sh` |
| `systemd` | Предоставя `systemd-inhibit`, който блокира idle/sleep по време на запис | Конзолата проверява наличието му още при стартиране |
| `wireshark-common` | Предоставя `dumpcap`, който записва PCAPNG | Задължителен за конзолата |

| `hcxtools` | Предоставя `hcxpcapngtool`, който извлича PMKID/EAPOL за режим 22000 | Live индикация и експорт за Hashcat |
| `hashcat` | Проверява речник срещу експортираните WPA данни | Меню Hashcat |
| `ca-certificates` | Проверка на HTTPS сертификатите при изтегляне на речници | Изтегляне през Python `urllib` |

Инсталация за пълната конзола:

```bash
sudo apt update
sudo apt install python3 bash sudo iw rfkill iproute2 systemd \
  wireshark-common tshark hcxtools hashcat ca-certificates git
```

Ако пакет липсва в конфигурираните хранилища, провери дали Ubuntu компонентът `universe` е включен. При въпрос от инсталатора дали обикновени потребители да записват пакети, тази конзола може да се използва и с отговор „Не“, защото изисква `sudo`. Добавяне в групата `wireshark` не премахва тази проверка в кода.

### GPU backend

Самият пакет `hashcat` не е достатъчен без подходящ compute runtime/драйвер. На проверената машина съществуващата NVIDIA конфигурация вече работи според `hashcat -I`; няма нужда да се сменя драйвер само за проекта. За друга машина избери поддържания за нейния GPU драйвер чрез Ubuntu Additional Drivers и следвай изискванията на Hashcat. CUDA toolkit не е универсална задължителна зависимост за всички GPU и backend-и.

```bash
nvidia-smi  # само за NVIDIA
hashcat -I
```

При CPU-only конфигурация Ubuntu пакетът `pocl-opencl-icd` е възможен OpenCL runtime; използването му с този проект не е проверено локално. CPU проверките обикновено са по-бавни. Не използвай `--force` за заобикаляне на проблемен backend.

### Пакети по избор

- `wireshark`: графичен преглед на PCAPNG, без да е нужен за менюто. Стартирай го като обикновен потребител.
- `python3-gi`, `gsettings-desktop-schemas`, `gnome-settings-daemon-common`: за отделното меню за GNOME заспиване; не са нужни за основната конзола.
- Aircrack-ng, hcxdumptool, John the Ripper, Wifite и Kismet са обсъдени в помощни документи, но текущият код не ги изисква.

```bash
sudo apt install wireshark
# Само ако ще използваш sleep-settings.py в GNOME:
sudo apt install python3-gi gsettings-desktop-schemas gnome-settings-daemon-common
```

## Подготовка и стартиране

Клонирай като обикновен потребител, за да остане проектът твоя собственост:

```bash
git clone https://github.com/ivohtanev/wifi-bee.git
cd wifi-bee
/usr/bin/python3 -c 'import curses, fcntl; print("Python OK")'
iw dev
iw list
```

В `iw list` потърси `monitor` в Supported interface modes. В `wifi-monitor.sh` физическият интерфейс е зададен като `IFACE=wlp44s0`, а monitor интерфейсът е `MON=wifi_mon`. Това отговаря на локалната конфигурация. На друга машина редактирай **IFACE** според `iw dev`. Конзолата също очаква `wifi_mon`, затова запази това име. Няма CLI опция за друг интерфейс.

```bash
sudo ./wifi-monitor.sh start
./wifi-monitor.sh status
sudo /usr/bin/python3 ./wifi-console.py --owner "$(id -un)"
```

Изпълни последната команда от терминала на обикновения си потребител; така `id -un` подава неговото име преди `sudo`. `--owner` определя собственика на записите. Без тази опция се използва собственикът на папката на проекта.

Скриптът добавя monitor интерфейс върху същото радио. Не спира NetworkManager. Двата интерфейса не получават независими радиа: едновременната Wi-Fi връзка може да пречи на избора на канал. За интернет по време на запис използвай Ethernet/USB tethering или отделен адаптер. Не пускай други програми, които сменят канала на същото радио.

## Как се използва

### 1. Запис

Избери **1. Всички пакети (dumpcap)** или **2. Всички без служебен шум**. Втората опция отстранява избрани control/null кадри; тя не е филтър само за authentication и не ограничава записа до конкретен BSSID. Пази beacon/probe и останалия приет трафик според филтъра в кода.

Използвай **Канал**, за да зададеш разрешения канал на тестовата мрежа, после **Старт**. Програмата не прави channel hopping. За наблюдение на handshake остави собствен клиент да се свърже нормално към мрежата, докато записът работи. **Стоп** приключва серията и прибира файловете в `captures/`.

↑/↓ избира, Enter потвърждава, Q/Esc връща назад. В екрана за запис връщането назад спира записа. PgUp/PgDn превърта устройствата. Ctrl+C отваря потвърждение с подразбиращ се отказ. Броячите включват повторни предавания; MAC адресите не са брой уникални физически устройства. Зелена hcx индикация означава приети данни от конвертора, не непременно пълен M1–M4 обмен или намерена парола.

### 2. Анализ и експорт

След спиране избери **3. Анализ на записи** → серия → **Всички от серията** или отделен файл. Цяла серия позволява съвместна обработка на обмен, разделен между ротации. Менюто намира PCAPNG файловете в `captures/`, чиито имена започват с числовия номер на серията; няма общ файлов диалог за произволен PCAP.

От резултата можеш да извлечеш:

- **Готови за hashcat 22000** → `data/ready/<id>/`, с `wpa.22000`, manifest и converter log. Предлага се при приети записи.
- **Кеш / частични данни** → `data/cache/<id>/`, с оригинали и TSV. Кешът включва доказателствата от анализа и не означава само непълни handshake-и.

Експортът е изричен избор. Приет WPA запис не гарантира, че паролата присъства в речника. WPA3-SAE не се проверява по същия начин като WPA/WPA2-PSK в режим 22000.

### 3. Речници и Hashcat

От **5. Речници — изтегляне** избери списък и натисни Enter. Изтеглянето проверява SHA-256 спрямо фиксирания каталог; Q/Esc отменя. Може да добавиш собствен текстов файл с един кандидат на ред в `wordlists/` (`.txt`, `.dic`, `.lst`, `.wordlist`) или да въведеш пълния му път при избор на речник.

В **4. Hashcat** → **Нова речникова проверка** избери експортиран `data/ready` набор, речник и потвърди старта. Използват се режим `22000`, речникова атака `-a 0` и workload `-w 1`. Екранът показва прогрес, скорост, ETA, резултати и налична GPU телеметрия. `Exhausted` означава, че речникът е изчерпан; `Cracked` — намерено съвпадение срещу записаните данни, което не доказва текущата парола на рутера.

Резултатите са в `data/hashcat/<задача>/recovered.txt` и `hashcat.potfile`. От **Предишни задачи / резултати / възобновяване** можеш да ги прегледаш и да възобновиш задача с наличен checkpoint. Запази цялата папка и непроменения речник на същия път. `run.json` е отчет за състоянието; реалното възобновяване зависи от checkpoint на Hashcat, а не от честотата на обновяване на екрана.

### 4. Приключване и заспиване

Излез от конзолата след спиране на работата, после премахни monitor интерфейса:

```bash
sudo ./wifi-monitor.sh stop
```

По време на радиозапис `systemd-inhibit` блокира idle/sleep. Това не е постоянна промяна в GNOME настройките и не гарантира защита от принудително изключване. Ако искаш отделно да промениш автоматичното заспиване в GNOME, изпълни **без sudo**, в собствената си графична сесия:

```bash
/usr/bin/python3 ./sleep-settings.py --status
/usr/bin/python3 ./sleep-settings.py
```

## Файлове, поверителност и проблеми

`captures/`, `data/`, `log/`, `wordlists/`, `.backups/` и локалните броячи са изключени от Git. Записите могат да съдържат MAC адреси, SSID и трафик, а резултатите — пароли в открит вид. `.gitignore` предотвратява обичайното добавяне, но не криптира файловете. Не ги добавяй с `git add -f`.

Записът временно е в `/var/tmp/.recording-*`, а при нормално спиране се премества в `captures/`. След авария временната папка може да остане; запази я преди ръчно възстановяване. Няма автоматично възстановяване след срив. При недостатъчно място провери както крайната, така и временните папки.

При „няма интерфейс“ провери `iw dev` и `IFACE`; при блокирано радио — `rfkill list`. При AppArmor отказ при четене виж [диагностиката за TShark](tshark-access-diagnosis.md): root права сами по себе си не заобикалят профила. Примерният `/path/to/wifi-bee` трябва да бъде заменен с действителния път, ако прилагаш описаното локално правило. При GPU грешка започни с `hashcat -I`; при съкращено меню увеличи терминалния прозорец.

Проверка на Python логиката, без радиозапис или GPU натоварване:

```bash
/usr/bin/python3 -m unittest discover -s tests
```

Тестовете използват симулации и не заменят хардуерен тест. При актуализация спри работата, изпълни `git pull --ff-only` и стартирай програмата отново.

Допълнителни детайли: [мониторинг и съхранение](MONITORING.md), [речници и възобновяване](WORDLISTS.md). По-старите хронологични бележки в другите документи могат да описват предишно поведение; горните стъпки следват текущия код.

## Източници

Пакетите и локалната конфигурация са проверени с `dpkg-query`, `/etc/os-release`, `iw list`, `nvidia-smi` и `hashcat -I`. Обосновката за зависимостите следва реалните извиквания в кода.

- [Ubuntu: wireshark-common](https://packages.ubuntu.com/wireshark-common) — пакет с общите инструменти на Wireshark.
- [Wireshark: dumpcap](https://www.wireshark.org/docs/man-pages/dumpcap.html) — запис и ротация.
- [hcxtools](https://github.com/ZerBea/hcxtools) — конвертиране на Wi-Fi записи.
- [Hashcat: изисквания за backend и драйвери](https://hashcat.net/hashcat/) — зависимости според производителя на GPU.
