# Wi-Fi и инструменти за проверка на пароли

Практически справочник за Ubuntu. Примерите са за собствена мрежа, собствени файлове или среда, за която имаш разрешение за тестове.

## 1. Кой инструмент за какво служи

| Пакет / инструмент | За какво е | Какво прави на практика |
| --- | --- | --- |
| `aircrack-ng` | Комплект за Wi-Fi одит | Включва `airmon-ng` за monitor mode, `airodump-ng` за наблюдение и запис на 802.11 кадри и `aircrack-ng` за офлайн проверка на кандидати за пароли. Самият `aircrack-ng` не използва CUDA като Hashcat. |
| `wireshark` | Графичен анализ на трафик | Отваря `.cap`, `.pcap` и `.pcapng`, показва кадрите подробно и позволява филтриране по протокол, адрес и други полета. |
| `tshark` | Терминален анализ на трафик | Прави запис, филтрира съществуващи записи и извлича полета за справки и скриптове. Използва анализатора на Wireshark. |
| `hcxdumptool` | Специализиран Wi-Fi запис и одит | Записва данни в `.pcapng`. Има пасивни и активни режими; обикновено стартиране без уточняване на режима не трябва да се приема за пасивно. |
| `hcxtools` | Обработка на Wi-Fi записи | Комплект помощни програми. Основната тук е `hcxpcapngtool`, която извлича подходящи PMKID/EAPOL данни във формат за Hashcat. Не проверява сама паролите. |
| `hashcat` | Офлайн проверка на кандидати за пароли | Използва GPU/CPU и сравнява кандидати с предоставени хешове. За WPA-PBKDF2 PMKID/EAPOL се използва режим `22000`; при твоята конфигурация вече е тествана CUDA. |
| `john` — John the Ripper | Офлайн възстановяване на пароли | Поддържа различни хешове; наличните формати зависят от версията. Jumbo изданието има повече формати от стандартния пакет. При проверката за този справочник командата `john` не беше открита. |
| `wifite` | Автоматизиране на Wi-Fi одит | Управлява други инструменти за избор на мрежа, запис и проверка. Част от режимите са активни и могат да прекъснат връзки; не е просто монитор. |

**Важно разграничение:** monitor mode означава приемане на сурови Wi-Fi кадри. Това не доказва поддръжка на packet injection и не разкрива автоматично съдържанието на криптиран трафик. WPA3-SAE не се проверява по същия начин като WPA/WPA2-PSK чрез режим `22000`.

## 2. Подготовка и означения

В примерите замени:

| Стойност | Значение |
| --- | --- |
| `wlan0` | Реалното име на Wi-Fi интерфейса от `iw dev`, например `wlp3s0` |
| `wlan0mon` | Името на monitor интерфейса след `airmon-ng`; провери го с `iw dev` |
| `02:11:22:33:44:55` | Примерен BSSID; използвай адреса на собствения тестов access point |
| `6` | Реалния канал на тестовата мрежа |
| `lab-01.cap` / `lab.pcapng` | Собствен запис на Wi-Fi кадри |
| `lab.22000` | Извлечени данни за офлайн проверка, а не файл с пароли |
| `candidates.txt` | Текстов файл с по един кандидат за парола на ред |

Създай работна папка и малък тестов речник:

```bash
mkdir -p wifi-lab
cd wifi-lab
printf '%s\n' 'LabPassword2026!' 'AnotherLabPass!' > candidates.txt
```

Това са демонстрационни кандидати, не препоръчани реални пароли.

Провери интерфейсите:

```bash
iw dev
ip -brief link
```

Работата в monitor mode може да прекъсне Wi-Fi връзката през същия адаптер. За удобство използвай Ethernet или втори адаптер. Командите за четене на файлове обичайно не изискват `sudo`.

## 3. Aircrack-ng

### 3.1. Интерфейси и monitor mode

```bash
sudo airmon-ng
sudo airmon-ng check
sudo airmon-ng start wlan0
iw dev
```

`check` показва потенциално пречещи процеси. Името след стартирането може да е различно от `wlan0mon`; използвай действителното име в следващите команди.

### 3.2. Наблюдение и запис на собствената тестова мрежа

```bash
sudo airodump-ng --bssid 02:11:22:33:44:55 --channel 6 wlan0mon
```

За запис:

```bash
sudo airodump-ng --bssid 02:11:22:33:44:55 --channel 6 \
  --write lab --output-format pcap wlan0mon
```

Спиране: `Ctrl+C`. Обичайният първи файл е `lab-01.cap`. При нормално повторно свързване на собствен клиент може да се запише handshake. Самото наличие на `.cap` не означава, че има достатъчно данни за проверка на парола.

### 3.3. Офлайн проверка с малък речник

```bash
aircrack-ng -w candidates.txt -b 02:11:22:33:44:55 lab-01.cap
```

Проверява само кандидатите от файла. Неуспехът не доказва силна парола — тя може просто да липсва в речника или записът да е неподходящ.

### 3.4. Връщане към нормален режим

```bash
sudo airmon-ng stop wlan0mon
nmcli device status
```

Ако по време на теста си спрял NetworkManager, стартирай го отново с `sudo systemctl start NetworkManager`. След това се свържи към мрежата от обичайното меню.

## 4. Wireshark

### 4.1. Отваряне на запис

```bash
wireshark lab-01.cap
```

### 4.2. Отваряне с предварително зададен display filter

```bash
wireshark -r lab-01.cap -Y 'eapol'
wireshark -r lab-01.cap -Y 'wlan.bssid == 02:11:22:33:44:55'
```

Полезни филтри за полето над списъка с кадри:

```text
eapol
wlan.fc.type_subtype == 0x08
wlan.bssid == 02:11:22:33:44:55
```

Съответно: EAPOL обмен, beacon кадри и кадри за конкретен BSSID. Наличието на EAPOL пакети само по себе си не гарантира използваем handshake. Стартирай графичния Wireshark като обикновен потребител.

## 5. TShark

### 5.1. Интерфейси и кратък запис

```bash
tshark -D
sudo tshark -i wlan0mon -a duration:60 -w lab.pcapng
```

Записва 60 секунди от вече подготвен monitor интерфейс. Ако интерфейсът е в обикновен managed режим, няма да получиш същия набор сурови Wi-Fi кадри.

### 5.2. Четене и филтриране

```bash
tshark -r lab.pcapng -Y 'eapol'
tshark -r lab.pcapng -Y 'wlan.bssid == 02:11:22:33:44:55'
```

### 5.3. Извличане на beacon информация в TSV

```bash
tshark -r lab.pcapng -Y 'wlan.fc.type_subtype == 0x08' \
  -T fields -E header=y -e wlan.bssid -e wlan.ssid > access-points.tsv
```

Един access point може да се появява многократно, защото изпраща много beacon кадри.

### 5.4. Статистика по протоколи

```bash
tshark -r lab.pcapng -q -z io,phs
```

`-r` чете файл, `-Y` задава display filter, `-w` записва пакети. За текстова справка използвай пренасочване `>`, както в TSV примера.

## 6. hcxdumptool

Опциите по-долу са проверени спрямо локалната версия **7.0.0**. При този инструмент използвай физическия интерфейс, а не предварително създаден чрез `airmon-ng` виртуален monitor интерфейс. Не изпълнявай паралелно други програми, които сменят канала или управляват адаптера.

### 6.1. Помощ и информация за адаптера

```bash
hcxdumptool -h
sudo hcxdumptool -L
sudo hcxdumptool -I wlan0
```

### 6.2. Пасивно наблюдение на канал

```bash
sudo hcxdumptool -i wlan0 --rcascan=p -c 6a --rds=1
```

`--rcascan=p` избира пасивно сканиране; `6a` означава канал 6 в 2.4 GHz според означенията на този инструмент. `--rds=1` включва екранен отчет. Спира се с `Ctrl+C`.

Този пример е за наблюдение. За запис за следващите раздели използвай описаните `airodump-ng` или `tshark`. Не приемай, че обикновено `hcxdumptool -i wlan0 -w ...` е пасивен запис: инструментът има активни действия по подразбиране.

## 7. hcxtools / hcxpcapngtool

### 7.1. Помощ

```bash
hcxpcapngtool -h
```

### 7.2. Преобразуване на собствен запис за Hashcat

```bash
hcxpcapngtool -o lab.22000 lab-01.cap
```

Или при `.pcapng` запис:

```bash
hcxpcapngtool -o lab-from-pcapng.22000 lab.pcapng
```

Това са алтернативни примери. Прегледай отчета за намерени и записани PMKID/EAPOL записи. Ако няма подходящи данни, няма да се получи използваем хеш за Hashcat. Изходът се добавя към съществуващ файл — използвай ново име за отделен тест.

### 7.3. Проверка дали има изходни записи

```bash
wc -l lab.22000
head -n 1 lab.22000
```

Редовете съдържат данни за проверка, не оригиналната Wi-Fi парола. Пази записите и резултатите като чувствителни файлове.

## 8. Hashcat

### 8.1. Разпознат хардуер и benchmark

```bash
hashcat -I
hashcat -b -m 22000
```

Първата команда показва backend устройствата, втората измерва скорост за съответния алгоритъм. Benchmark резултатът не е гаранция за същата скорост при всяка реална задача.

### 8.2. Проверка на речник срещу собствен запис

```bash
hashcat -m 22000 -a 0 lab.22000 candidates.txt --session wifi-lab
```

`-m 22000` избира WPA-PBKDF2 PMKID/EAPOL, а `-a 0` проверява кандидати от речник. Това е офлайн работа; Wi-Fi адаптерът не е необходим на този етап.

### 8.3. Показване на намерените резултати

```bash
hashcat -m 22000 lab.22000 --show
```

Извежда резултатите, съхранени в potfile. Не стартира нова проверка.

### 8.4. Продължаване на запазена сесия

```bash
hashcat --session wifi-lab --restore
```

По време на работа `s` показва статус, а `c` заявява излизане при следващ checkpoint. Възстановяването изисква наличен restore файл и достъп до същите входни файлове.

`Exhausted` означава, че зададените кандидати са изчерпани. `Cracked` означава успешно намерен кандидат. Нито едно от тях не означава, че е проверено цялото възможно пространство от пароли.

## 9. John the Ripper

Този инструмент беше споменат в предишния списък, но при проверката не беше открит в PATH. Ако ти трябва:

```bash
sudo apt install john
```

### 9.1. Вграден тест

```bash
john --test=5
```

Изпълнява кратки тестове за поддържаните формати. Наличните формати зависят от компилацията.

### 9.2. Самостоятелна демонстрация със собствен тестов хеш

```bash
openssl passwd -6 -salt labsalt 'LabPassword2026!' > demo-sha512crypt.txt
john --wordlist=candidates.txt demo-sha512crypt.txt
john --show demo-sha512crypt.txt
```

Първата команда създава SHA-512-crypt хеш на известна демонстрационна парола; следващите я проверяват чрез малкия речник и показват резултата. Това е пример за локален password hash, а не WPA запис. Не подавай директно `lab.22000` на стандартния John с очакване, че форматът непременно е поддържан.

## 10. Wifite

### 10.1. Помощ и всички опции

```bash
wifite --help
wifite -h -v
```

### 10.2. Проверка на съществуващ запис

```bash
wifite --check lab-01.cap
```

Проверява записа чрез наличните помощни инструменти. Прочети отчета за липсващи зависимости и валидност на handshake.

### 10.3. Команди за офлайн проверка на записите

```bash
wifite --crack
```

Показва команди за проверка на намерени записи в структурата, която Wifite използва. Ако няма собствени записи в нея, може да няма какво да покаже.

### 10.4. Ограничен тест към собствен access point

```bash
sudo wifite -i wlan0 -b 02:11:22:33:44:55 --wpa \
  --no-wps --no-pmkid --nodeauths --skip-crack
```

Ограничава избора до посочения BSSID, изключва WPS/PMKID методите, забранява deauthentication и пропуска проверката на паролата. Изчаква подходящ обмен при нормално свързване на клиент. Това е автоматизация и може да промени режима на адаптера; прегледай изхода и спри с `Ctrl+C`, когато приключиш. Не добавяй масовите опции `--infinite`, `--first` или `-p` към този пример.

## 11. Как се свързват инструментите

Типична последователност за собствена WPA/WPA2-PSK лабораторна мрежа:

1. `airmon-ng` подготвя интерфейса за monitor mode.
2. `airodump-ng` записва кадрите от собствения access point.
3. `Wireshark` или `tshark` помага да прегледаш записа.
4. `hcxpcapngtool` извлича подходящите данни в `.22000`.
5. `hashcat` проверява конкретен списък кандидати офлайн.
6. `airmon-ng stop` връща интерфейса към нормална употреба.

`hcxdumptool` е отделен вариант за работа с радиото, а Wifite автоматизира части от процеса. Не е необходимо всички програми да работят едновременно.
